### Step 3 — Explain (Root-Cause Agent) (60s)

**Action**: Click **"Explain"** on the **JI-02 Orphan OS Rate** alert (RED).

**Say**: "The Root-Cause Agent fetches the actual failing records from Databricks and asks Bob to identify the pattern."

**What happens**:

**Key message**: "Bob reads the actual data, not generic rules. It identified the bulk-import failure pattern from the record contents."

## Fallback Script (No Bob API)

If Bob API is unavailable during the demo (VPN issue, token expired, etc.):

1. **Monitor Agent** → rule-based fallback generates canned alerts for each RED KPI
   (same data, pre-written explanations instead of Bob-generated)
2. **Root-Cause Agent** → FALLBACK_ANALYSES dict returns pre-written analyses for
   JI-02, CS-07, RI-05, CS-02 (the primary demo KPIs)
3. **Remediation Agent** → uses `suggested_sql` from root-cause fallback analysis
4. **Summary Agent** → `_fallback_summary()` builds a rule-based narrative from worst/best KPIs
5. **Chat Agent** → keyword matching on "orphan", "ghost", "fix", "trend" → canned replies

**Key message for fallback**: "The dashboard works fully without Bob credentials — but Bob turns the canned alerts into specific, persona-addressed insights that would take hours to write manually."

## Technical Q&A (If Asked)

**Q: How does Bob authenticate?**  
A: `agents/bob_client.py` tries Bob Shell CLI subprocess first (handles VPN/BFF auth). Falls back to direct HTTP with the OAuth token decrypted from Bob IDE's local SQLite store using Windows DPAPI + AES-256-GCM. User-Agent is set to `bobshell/1.0.6` to pass Cloudflare WAF.

**Q: Is the data real or mocked?**  
A: The Databricks tables contain seeded sample data with intentionally baked-in anomalies (100 orders, 111 shipments, 113 OS rows). The anomalies are realistic representations of issues found in production Transport Analytics deployments. The Remediation Agent applies a real SQL UPDATE — not a mock.

**Q: Can this work on a different dataset?**  
A: Yes. The KPI definitions, drill-down queries, and agent prompts are all parameterised. The three-tier agent pattern is reusable for any domain with measurable KPIs and a relational database.

**Q: What is the Bob token approach?**  
A: The Bob IDE stores a ~24h OAuth session token in an encrypted local SQLite database. `bob_client.py` decrypts it at runtime — no hardcoded credentials. Token auto-refreshes each time Bob IDE is opened.
